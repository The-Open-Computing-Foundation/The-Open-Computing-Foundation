Proposed objectives

These are proposed objectives for The Web Independence Initiative and Ubiquity. They are a planning framework, not completed milestones, delivery commitments or a dated roadmap. Priorities should be revised in response to evidence and contributor participation.

Short term: establish a tractable scope

  • Define terminology for web access, local execution, web-native implementation and partial compatibility.
  • Identify representative software categories and choose small, lawful test cases with understandable dependencies.
  • Document source availability, licence conditions, data formats, platform APIs and required services for each candidate.
  • Map requirements to web standards and record known gaps, rather than assuming equivalent browser features exist.
  • Draft a compatibility-report format that records both successful tasks and failures.

A useful outcome would be a reviewable set of questions and test plans. Scope definition should include exclusion criteria, such as inaccessible licensed components or indispensable privileged drivers. No completed inventory is asserted.

Medium term: investigate reproducible approaches

  • Develop bounded proof-of-concept ports or reimplementations where permissions and technical scope permit.
  • Compare source-level porting, runtime adaptation and emulation against the same defined task where appropriate.
  • Create reproducible correctness, interaction and performance tests across browser engines and devices.
  • Test import, export and recovery under interruption, storage pressure and unavailable services.
  • Document deployment constraints, accessible operation and the ongoing cost of maintaining each approach.

An experiment should demonstrate a stated behaviour and disclose its limits. A successful proof of concept would be a basis for further investigation, not evidence that an application’s complete feature set is supported.

Long term: explore reusable infrastructure

  • Identify repeated compatibility requirements and investigate reusable interfaces only where experiments justify them.
  • Broaden the categories and workflows studied as technical and maintenance capacity permits.
  • Develop maintainable relationships between upstream software, browser adaptations and compatibility documentation.
  • Improve portability of user data and reduce dependence on individual services or distribution systems.
  • Support contributor stewardship of the research agenda, technical standards and shared documentation.

Long-term breadth depends on achievable engineering, rights, browser capabilities and sustained maintenance. Some categories may remain unsuitable for web execution. The objective is useful, demonstrated access rather than a universal compatibility claim.

How objectives should be evaluated

Progress should be described through published methods, inspectable changes and reproducible observations. A proposal should identify its assumptions, expected outcome, known risks and conditions for stopping or changing direction.
